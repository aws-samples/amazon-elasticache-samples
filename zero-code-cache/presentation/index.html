Remote Query Cache Plugin

How it works — step by step

1

You add a SQL hint

/* CACHE_PARAM(ttl=300s) */ SELECT * FROM products WHERE ...

2

Wrapper intercepts the query

Parses the CACHE_PARAM hint, extracts TTL, generates cache key from query + user + schema

3

Cache HIT → returns result in <1ms

Database is never touched. Result deserialized from Valkey.

4

Cache MISS → queries database

Returns result to app immediately. Writes to Valkey asynchronously in background.

5

Next identical query → instant cache hit

Served from Valkey until TTL expires. Zero database load.

The Code Changes

Two changes. That's it.

Before — Plain JDBC

// DataSource

driver = "org.postgresql.Driver"

url = "jdbc:postgresql://..."

// Query

SELECT * FROM products

WHERE category = 'Laptops'

After — With Cache

// DataSource

driver = "software.amazon.jdbc.Driver"

url = "jdbc:aws-wrapper:postgresql://..."

wrapperPlugins = "remoteQueryCache"

cacheEndpointAddrRw = "mycache:6379"

// Query

/* CACHE_PARAM(ttl=300s) */

SELECT * FROM products

WHERE category = 'Laptops'

Zero application logic changes. The agent code doesn't change at all.

Getting Started

5 steps to production-ready caching

1

Add the JDBC wrapper dependency

aws-advanced-jdbc-wrapper v4.4.0 + valkey-glide + commons-pool2

2

Switch the JDBC driver and URL

software.amazon.jdbc.Driver + jdbc:aws-wrapper:postgresql://

3

Add 3 properties

wrapperPlugins=remoteQueryCache, cacheEndpointAddrRw, cacheUseSSL

4

Add SQL hints to cacheable queries

/* CACHE_PARAM(ttl=300s) */ SELECT ...

5

Deploy — done

Your queries are now cached in Valkey. No other changes needed.
